# biletix-mcp 🇹🇷

mcp-name: io.github.mohammad-abbasi-sh/biletix-mcp

سرور MCP غیررسمی و **فقط‌خواندنی** برای biletix.com — بزرگ‌ترین پلتفرم بلیت ترکیه (متعلق به Ticketmaster): کنسرت، تئاتر، جشنواره، ورزش — رویدادهای شاخص/داغ، جست‌وجوی کلیدواژه + شهر در فهرست شاخص‌ها، جزئیات کامل رویداد (مکان، تاریخ‌ها، کمترین قیمت، موجودی)، رویدادها بر اساس دسته، مکان‌ها و رویدادهای آیندهٔ هر مکان.

> ساختهٔ محمد عباسی در چارچوب «کارخانهٔ MCP ترکیه» (خط لوله به سبک سپهر). وابسته به biletix.com نیست.

## برای ایجنت‌های هوش مصنوعی

به پیکربندی کلاینت MCP خود اضافه کنید (stdio):

```json
{
  "mcpServers": {
    "biletix": {
      "command": "uvx",
      "args": ["biletix-mcp"]
    }
  }
}
```

یا به‌صورت محلی اجرا کنید: `python -m biletix_mcp.server` (نیازمند `mcp<2` و `curl-cffi`).

## ابزارها

| ابزار | توضیح |
|------|-------------|
| `biletix_trending` | رویدادهای شاخص — `section`: ‏"browse" («Etkinliklere Göz Atın»، ۴۳ رویداد)، ‏"starting_soon" («24 Saat İçinde Başlayacaklar»، ۵۰ رویداد)، "all" (۹۲ رویداد متمایز)؛ `limit` ۱ تا ۵۰ |
| `biletix_search_events` | جست‌وجوی کلیدواژه در رویدادهای شاخص صفحهٔ اصلی — `query` («Simge»، «caz»)، `city` اختیاری («istanbul»، «ankara»)؛ `limit` ۱ تا ۵۰ |
| `biletix_get_event` | جزئیات کامل یک رویداد — `event_url` (همان URL که ابزارهای trending/search برمی‌گردانند)؛ نام، توضیحات، شروع/پایان، وضعیت، مکان (+ شهر، مختصات، URL صفحهٔ مکان)، کمترین قیمت به لیر، موجودی، تصویر |
| `biletix_list_by_category` | رویدادهای شاخص یک دسته — `category`: پیشوند slug در URL، مثل «music»؛ همچنین دسته‌های موجود در صفحهٔ اصلی امروز را برمی‌گرداند |
| `biletix_list_venues` | مکان‌های پشت رویدادهای شاخص (شهر + تعداد رویداد شاخص)؛ `limit` ۱ تا ۵۰ |
| `biletix_venue_events` | رویدادهای آیندهٔ یک مکان — `venue_url` (فیلد `venue_url` در خروجی `biletix_get_event`)؛ `limit` ۱ تا ۵۰ |

## نحوهٔ کار

biletix.com صفحهٔ اصلی (`/anasayfa/TURKIYE/tr`)، صفحات جزئیات رویداد (`/etkinlik/<code>/TURKIYE/tr/<slug>`)، صفحات گروه رویداد (`/etkinlik-grup/<id>/...`) و صفحات مکان (`/mekan/<code>/...`) را کاملاً سمت سرور رندر می‌کند — بدون ورود، کلید API و کوکی. صفحهٔ اصلی خام (`/`) فقط یک ریدایرکتور جاوااسکریپت ۱٫۱ کیلوبایتی است (`redirector.js` ← `/anasayfa/TURKIYE/tr`). دو بخش صفحهٔ اصلی سمت سرور رندر می‌شوند: «Etkinliklere Göz Atın» (۴۳ کارت) و «24 Saat İçinde Başlayacaklar» (۵۰ کارت)؛ «Popüler Etkinlikler» و «Biletix'te Yeni Satışta» فقط سمت کلاینت بارگذاری می‌شوند. کارت‌های رویداد میکرودیتای schema.org دارند (عنوان، شروع/پایان، مکان + شهر، کمترین قیمت به لیر، دسته + تاریخ + شهر در slug، مثل `music-aura-16-11-2026-istanbul`)؛ کارت‌های گروه/تور (`/etkinlik-grup/...`، مکان «Çeşitli Mekanlar») همان قالب را دارند. صفحات جزئیات یک بلوک کامل Event از نوع JSON-LD دارند (توضیحات، مکان با آدرس + مختصات، قیمت/موجودی). قیمت‌ها در متن نمایشی به قالب ترکی هستند («1.995₺» ← ۱۹۹۵٫۰؛ «3.171,25₺» ← ۳۱۷۱٫۲۵). صفحات `/search` و `/category` پوستهٔ Angular هستند و اندپوینت `/api/v1/searchquery/searchSuggestion` در فراخوانی مستقیم به صفحهٔ 404 ریدایرکت می‌شود؛ پس جست‌وجوی کلیدواژه به فهرست شاخص‌های صفحهٔ اصلی محدود است (در زمان ساخت ۹۲ رویداد متمایز). اسکریپت‌های اتاق انتظار Queue-it روی صفحهٔ جست‌وجو بارگذاری می‌شوند اما دریافت‌های SSR را مسدود نمی‌کنند. انتقال با جعل TLS کروم انجام می‌شود (`curl-cffi`، `chrome120`)؛ درخواست‌ها با فاصلهٔ ~۰٫۸ ثانیه؛ همه‌چیز فقط‌خواندنی است.

## نصب

```bash
uvx biletix-mcp        # اجرای مستقیم (نیازمند uv)
# یا
pip install biletix-mcp
biletix-mcp    # سرور MCP را روی stdio راه می‌اندازد
```

## تست‌ها

```bash
python -m venv .venv && .venv/bin/pip install -e .
.venv/bin/python -m unittest discover -s tests -v
```

تست‌های آفلاین روی صفحات واقعیِ ضبط‌شده اجرا می‌شوند (دریافت‌شده در ۲۰۲۶-۱۱-۰۷)؛ تست‌های زنده به biletix.com وصل می‌شوند. ۲۴/۲۴ سبز (۱۵ آفلاین + ۹ زنده) + تست دود MCP روی stdio.

## نقشهٔ راه

- جست‌وجوی کامل کاتالوگ (نیازمند API جست‌وجوی سمت کلاینت سایت یا نقشهٔ سایت URLهای رویداد)
- دسته‌های بلیت / قیمت‌های طرح صندلی برای هر رویداد (فعلاً فقط قیمت «از»)
- صفحات هنرمند (`/etkinlik-grup/...` همین حالا تاریخ‌های تور را فهرست می‌کند)
